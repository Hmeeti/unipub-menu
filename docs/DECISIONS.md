# Архитектурные и продуктовые решения

Здесь фиксируются решения, принятые там, где ТЗ допускало несколько вариантов
или где требования конфликтовали. Формат: решение → причина.

## Платформа

- **Next.js 16 (App Router, Turbopack), React 19, TypeScript 5.9 strict.** TS 7 пока
  несовместим с typescript-eslint (`<6.1`), поэтому остаёмся на 5.x.
- **Middleware называется `src/proxy.ts`** (переименование в Next 16), runtime nodejs.
- **CSP с nonce ⇒ страницы рендерятся динамически.** Nonce несовместим с ISR/PPR
  (Next кладёт nonce только в динамический HTML). Поэтому кэшируется не HTML, а
  данные меню: `unstable_cache` с тегом `menu`; админка вызывает
  `revalidateTag("menu", { expire: 0 })` — стоп-лист применяется сразу.
  `cacheComponents` не включаем по той же причине.
- **`style-src-attr 'unsafe-inline'`** разрешён: React выставляет inline `style`
  (позиции анимаций, размеры изображений). Скрипты — только по nonce.
- **Без Motion, vaul, otplib.** Анимации — CSS + WAAPI (экономия ~40 KB gzip в
  бюджете 120 KB), bottom sheet — своя реализация на Radix Dialog со свайпом,
  TOTP — собственная реализация RFC 6238 (≈60 строк, покрыта тест-векторами RFC).
- **Sentry опционален** и не подключён по умолчанию: логи pino в stdout (JSON),
  `/api/healthz` проверяет БД и Redis.

## Локальная разработка

- **`npm run dev` — одна команда без Docker.** Если `DATABASE_URL` не задан,
  используется встроенный PGlite (`.data/pglite`, в тестах — in-memory) с
  автомиграцией и автосидом из `legacy/menu-data.js`. Если не задан `REDIS_URL` —
  in-memory KV. В production/staging оба обязательны (проверяет `src/lib/env.ts`).
- **`WORKER_MODE=inline`** (dev/staging) запускает outbox-воркер внутри процесса
  Next; в production — отдельный контейнер `worker`.

## Данные

- **Источник истины при импорте — `js/menu-data.js`**, `data/menu.json` используется
  только для сверки. Расхождения (например, цена s1 3900 vs 4900, состав тартара
  RU 6 / KZ 4 / EN 5 ингредиентов) пишутся в `docs/import-report.md`.
- **Код языка `kz` → `kk`** (ISO 639-1), маршрут `/kk`.
- **Аллергены нормализованы** в справочник 14 аллергенов ЕС с переводами;
  русские строки из старого меню сопоставлены через словарь синонимов.
- **Телефоны официантов не переносятся** (ТЗ: без личных телефонов); пустая ссылка
  Telegram в контактах отброшена. Оба факта отражены в отчёте импорта.
- **Вес/время приготовления хранятся как I18nText** («320 г», «на 2 чел.»,
  «до 8 гостей»): в старом меню это свободный текст, не число.
- **Сумма сервиса хранится в базисных пунктах** (`service_rate_bp = 1500` = 15%),
  деньги — целые тенге.
- **Публикация:** черновик = рабочие таблицы; «Опубликовать» = снимок в
  `menu_versions` (последний — живой); откат = восстановление снимка в черновик и
  новая публикация с `restored_from`. Стоп-лист, акции, официанты, залы и
  feature-флаги — «живые» данные вне снимка, чтобы стоп-лист не требовал публикации.
- **Номер заказа за «бизнес-день»** с границей 06:00 Asia/Almaty: заказ в 01:30
  относится к предыдущему дню (бар работает до 02:00).
- **Asia/Almaty = UTC+5** (tzdata 2026b, ICU в Node 24); расписания вычисляются
  через `Intl` с зоной, а не смещением.
- **Расписания через полночь** (`from 22:00 to 02:00`) относятся к дню начала:
  акция «пятница 22–02» активна в субботу в 01:00.

## Безопасность и заказы

- **Токен стола:** `CODE.version.sig` — HMAC-SHA256 (base64url, 22 символа) от кода и
  версии. Перевыпуск QR = инкремент `token_version`, старые QR перестают работать.
- **Коды столов — только латиница и цифры, до 8 символов** (`VIP1`, `V2`, `12`):
  QR-PDF рендерится без встраивания кириллического шрифта, коды однозначно
  набираются с любой раскладки. Подписи залов на печатной HTML-странице — кириллица.
- **Лимиты (fixed window в Redis):** с QR — стол 8/10 мин, сессия 6/10 мин, IP 80/10 мин
  (весь бар на одном Wi-Fi); без QR — 3/2/20 за 15 мин. Блокировок на часы нет.
  Turnstile включается только при подозрительной активности с IP (≥30 попыток).
- **Бронь и PII:** имя и телефон НЕ пишутся в таблицы. Для надёжной доставки
  через outbox полезная нагрузка шифруется AES-256-GCM (`DATA_ENCRYPTION_KEY`) и
  после успешной отправки в Telegram затирается (`payload` → только номер заявки).
  Если доставка окончательно не удалась (dead), payload затирается через 24 ч.
  Это осознанный компромисс между «не хранить PII» и «не терять заявки».
- **IP хранится только как HMAC-хэш** (`APP_SECRET`) — для лимитов и расследований.
- **Пароли — argon2id** (m=19 MiB, t=2, p=1, рекомендация OWASP).

## Хостинг

- **Один VPS, Docker Compose:** app, worker, postgres 18, redis 8, caddy, backup.
  Staging — профиль `staging` в том же compose (отдельная БД `unipub_staging`,
  Redis db 1, свой поддомен с basic auth).
- **Cloudflare перед Caddy:** Caddy доверяет `CF-Connecting-IP` только из
  диапазонов Cloudflare (`trusted_proxies`), приложение читает `X-Real-IP` от Caddy.
- **Бэкапы:** ежедневный `pg_dump -Fc` в R2 в 05:15 Asia/Almaty, хранение 14 дней,
  `restore.sh` с явным подтверждением.

## Производительность

- **«~120 KB gzip на маршрут меню» недостижимо буквально:** голый Next 16 + React 19
  (пустая страница, только рантайм и роутер) — уже 127 KB gzip. Поэтому бюджет
  разделён: `scripts/check-budget.mjs` вычитает загрузку эталонного маршрута
  `/ru/__budget_baseline__` (404 без клиентского кода) и проверяет **код меню ≤45 KB**
  и **всего ≤175 KB**. Факт фазы 1: фреймворк 127.4 KB · меню 32.7 KB · всего 160.1 KB.
  Полифилы `nomodule` (core-js) современные браузеры не загружают — не считаются.
  В Next 16 сборка не печатает First Load JS, поэтому считаем по реально загруженным
  скриптам production-сервера.
- **Ради бюджета:** без tailwind-merge и class-variance-authority (`cn` = clsx; классы
  позиционирования передаются только снаружи); next-intl на клиенте не используется
  (ICU-рантайм ~15 KB) — сервер отдаёт плоский словарь нужных неймспейсов, клиентский
  `useT()` делает только подстановку `{var}`; шторки, фильтры и корзина грузятся
  `dynamic(ssr:false)` и предзагружаются в idle.
- **Изображения:** свой loader `next/image` — собственные загрузки имеют готовые WebP
  320/480/640/960/1280 на CDN (без сервера-оптимизатора), Unsplash ресайзится
  параметрами (q=60). Первые 4 карточки — `loading="eager"` + `fetchPriority="high"`
  (`priority` в Next 16 устарел). Секции ниже первого экрана — `content-visibility:auto`
  с оценочной высотой: браузер не верстает их и не грузит их ленивые фото; переход по
  категории доводится второй мгновенной прокруткой после `scrollend`.
- **Шрифт:** Manrope (cyrillic + cyrillic-ext + latin) покрывает все казахские буквы,
  проверяется после сборки `scripts/check-fonts.mjs`. Предзагружаются только cyrillic и
  latin, cyrillic-ext (ә ғ қ ң ө ү һ) подгружается по `unicode-range`.
- **Lighthouse (mobile, simulate) в фазе 1:** A11y 100, BP 100, SEO 100, CLS 0,
  TBT 50 ms, **Performance 84–85, LCP 4.3 s.** LCP-элемент — фото первой карточки
  с внешнего Unsplash (холодное соединение в каждом прогоне). Устраняется в фазе 5
  переносом фото в своё хранилище (R2/CDN) с вариантами; до этого порог Performance в
  LHCI — `warn`, остальные категории и CLS — `error`.

## Публичное меню (фаза 1)

- **Вид сетка/список хранится в cookie `unipub_view`**, а не в localStorage: сервер
  рендерит нужную раскладку сразу, без сдвига после гидрации.
- **Тема и сплэш решаются inline-скриптом в `<head>` с nonce** до первой отрисовки.
  Сплэш — только первый визит за 24 ч, ≤1.2 с, закрывается тапом; не показывается при
  переходе по QR (`?t=`), ссылке на блюдо (`?dish=`, `#dish-`). При
  `prefers-reduced-motion` показывается без анимаций.
- **Старые ссылки `#dish-<id>` поддерживаются** и переписываются в `?dish=<id>`.
- **«Любой официант»** — явный вариант в выборе (по умолчанию), выбор запоминается.
- **Секция «Избранное» — первой** над категориями. Избранное лежит в localStorage,
  поэтому у вернувшегося гостя с избранным секция появляется после гидрации и сдвигает
  список вниз. Для новых гостей (и для Lighthouse) сдвига нет. Осознанный компромисс:
  хранить избранное на сервере ради этого не стоит.
- **Акции:** показываются по расписанию; ссылки только `https:`.
- **Radix и CSP:** react-remove-scroll вставляет `<style>` — nonce передаётся через
  `get-nonce` (`NonceProvider`). Модальные листы открываются программно, поэтому
  возврат фокуса реализован в `Sheet` (Radix возвращает фокус только на `Dialog.Trigger`).
- **Поиск:** упрощённый стемминг RU, транслит латиницей («shashlyk»), названия на
  других языках, неправильная раскладка (EN→RU), синонимы, аллергены и флаги; при
  поиске/сортировке — плоский список, стоп-лист в конце. Казахский стемминг не делаем:
  казахские названия ищутся по префиксу и через русские/английские названия.
